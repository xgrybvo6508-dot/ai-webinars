Cal из команды Applied AI пишет системные промпты Claude Code, поэтому рассказывает о нём изнутри. Устройство намеренно простое: инструкции, мощные инструменты (файлы, терминал, MCP) и модель, которая работает в цикле, пока сама не решит, что задача готова. Принцип Anthropic звучит так: «самое простое решение, которое работает». Сверху лёгкий интерфейс и система разрешений. На опасных действиях агент останавливается и спрашивает человека. Работает через API Anthropic, AWS Bedrock и GCP Vertex.

::fig agent-loop "Агент в цикле: инструменты, модель и момент, когда задача готова"

Здесь нет индексации и RAG. Claude изучает кодовую базу так же, как новый разработчик: ищет через glob, grep и find, смотрит результаты и ищет снова. Отсюда и главные сценарии. Можно разобраться в чужом коде («где реализована эта фича?», «расскажи по git-истории, как менялся этот файл»). Можно позвать его напарником для обдумывания: «изучи код, предложи 2–3 варианта реализации, файлы пока не трогай». Он пишет код и с нуля, и в больших существующих проектах, а ещё берёт на себя тесты, рефакторинг, коммиты, PR и работу с git.

> Ценность не в «умном индексе», а в том, как агент сам исследует код.

***

Первая привычка — **CLAUDE.md**, файл с правилами проекта: команды тестов, стиль, архитектура. Claude читает его из рабочей папки и из домашней директории, а другие файлы подключаются через `@путь`. Вторая привычка — следить за контекстом: в длинных сессиях историю чистят командой `/clear` или сжимают через `/compact`. Третья — ходить маленькими шагами. Сделал правку, прогнал тесты, проверил типы и линтер, закоммитил. Если агент «уехал», откатываешься к последнему коммиту.

::fig small-steps "Маленькие шаги: правка → тесты → линтер → коммит"

Модель мультимодальна, так что макет `mock.png` можно просто вставить и попросить сверстать. **Esc** останавливает агента и даёт поправить курс, двойной **Esc** откатывает назад по истории диалога. Фраза «think hard» помогает на сложных багах: начиная с Claude 4, модель думает и между вызовами инструментов. Сессий может быть несколько параллельно, в tmux или во вкладках: в Anthropic есть люди, которые ведут четыре сразу. Когда bash и встроенных инструментов уже не хватает, подключают MCP. В headless-режиме Claude работает в GitHub Actions и других автоматизациях. Модель меняют командой `/model`, а changelog в репозитории anthropics/claude-code стоит читать раз в неделю.

***

Из этого следуют три вывода. Хорошая структура проекта и понятные названия сразу улучшают результат. После обновления модели стоит перечитать CLAUDE.md: новые модели точнее следуют инструкциям, и старые «костыли» могут стать лишними. А чтобы несколько агентов делились контекстом, проще всего вести общий markdown-файл, который все они пишут и читают.

На практике начать можно так. Заведи CLAUDE.md со стеком, командами запуска и тестов и пятью-десятью правилами стиля. Перед каждой фичей сначала проси варианты без кода и только потом выбирай. Держи цикл «правка → тест → коммит» и не давай агенту делать огромные изменения за раз. Попробуй две параллельные сессии: одна пишет код, другая тесты или ревью. А рутину вроде ревью PR отдай Claude в GitHub Actions. Этот сайт тоже можно так кормить: headless Claude Code по расписанию берёт новые транскрипты и пишет черновики саммари.
