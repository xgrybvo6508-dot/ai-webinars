Field engineer Cursor берёт открытый репозиторий WordPress, где старые PHP-компоненты соседствуют с React, и показывает, как довести такую миграцию до конца. Метод состоит из четырёх шагов, которые она видела и внутри Cursor, и у клиентов. Сначала проводят аудит и пишут стратегию. Потом план превращают в тикеты. Тикеты отдают облачным агентам. Напоследок настраивают автоматизации, чтобы кодовая база снова не устарела. Опора всего процесса — облачные агенты. Они работают на удалённых Linux-машинах и продолжают, когда ноутбук закрыт. Ими можно управлять из браузера, из Slack и с телефона.

::fig small-steps "Аудит → план → тикеты → облачные агенты → автоматизации"

Для аудита есть встроенная команда `/canvas`. Агент изучает код и строит интерактивную картину: покрытие тестами по экранам, что мигрировать первым, где тестов нет совсем. Canvas можно править словами, публиковать для команды и выгружать в PDF. Параллельно в Plan mode пишется стратегия. Спикер просит добавить тесты против регрессий и mermaid-диаграмму архитектуры «до и после». Plan mode не трогает код, он выдаёт markdown-документ по шаблону из Confluence и сначала уточняет вопросы, например какой экран брать первым. Для планов она выбирает модель, которая лучше пишет, а для исполнения переключается на быструю и дешёвую.

> Одна задача — один PR. Гигантский PR на тысячи строк проверить невозможно.

***

Через плагин Atlassian план превращается в эпик Jira: у каждого тикета есть цель, объём, критерии приёмки, тесты и зависимости. Дальше одна фраза облачному агенту: найди мои тикеты, сделай отдельный PR на каждый и подтверди изменения скриншотами или видео. Агент поднимает окружение (первый раз 10–20 минут, потом оно сохранено), подключает те же MCP, что и локально, а при необходимости работает сразу в нескольких репозиториях. Фронтенд он проверяет сам: двигает мышью на своей виртуальной машине и присылает видео с подписанными фрагментами. Для облака спикер советует дешёвые модели, тогда, по её словам, вся миграция обходится примерно в $3–4. В Cursor так разбирают бэклог на выходных и смотрят PR в понедельник.

::fig agent-loop "Облачный агент: тикет → код → тест в браузере → видео → PR"

***

Последний шаг она считает самым недооценённым. Legacy появляется не сразу, а когда поддержкой никто не занимается заранее. Автоматизации — это облачные агенты по расписанию или по событию: открытый PR, сообщение в Slack, перенос тикета. Её любимый пример — «чистильщик feature flags»: раз в неделю ищет флаги, не использованные 30 дней, открывает PR с тестами и пишет в Slack. Есть шаблоны для покрытия тестами, поиска уязвимостей и первичного разбора инцидентов. У каждой автоматизации есть файл memories.md, так что она учится на замечаниях. Из ответов на вопросы: секреты и доступы к частным сетям настраиваются в облачном окружении, skills приходят вместе с плагинами, а плагин continual learning запоминает твой стиль в agents.md.

***

Что взять себе. Пройди эти четыре шага на любом своём старом проекте или открытом репозитории, и у тебя будет готовый кейс для портфолио. В промптах агентам всегда требуй отдельный PR на задачу и доказательство скриншотом или видео. Заведи свой skill `/onboard` для быстрого входа в чужой код. Отсюда же вырастает услуга для фриланса: миграция старых PHP-сайтов на React с отчётом и видео-проверкой каждого изменения.
